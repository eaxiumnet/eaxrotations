---

## Context

EaxAutoQuester is a Project Sylvanas auto-questing addon (15 Lua files, ~3,500 lines total). It drives quest automation through a Zygor guide integration with a polling state machine (IDLE → NAV → INTERACT → DO_ACTION → WAITING). Currently it has **zero tests**, **8 critical bugs**, **excessive pcall overhead**, **unused vendor_manager module**, and **violates AGENTS.md patterns**. This overhaul addresses all issues while maintaining full compatibility with EaxRotations.

### Task 2: pcall Audit & Safe Wrapper Design
**Description:** Audit every pcall usage across all 15 files. Design a `safe_api_wrapper.lua` wrapper that caches API availability at module load, eliminating per-frame pcall overhead for hot paths.

**Files to modify:**
- All 15 files (audit only, no changes yet)
- New: `safe_api_wrapper.lua` — central wrapper module

**Design:**
```lua
local M = {}

-- At module load, probe API availability once
function M.probe(api_fn)
    local ok, result = pcall(api_fn)
    if ok then return { available = true, fn = api_fn } end
    return { available = false }
end

-- Per-frame call: no pcall overhead if API is known-good
function M.call(probed, ...)
    if not probed.available then return nil end
    return probed.fn(...)
end

-- Fallback: pcall for unknown/fragile APIs
function M.call_pcall(api_fn, ...)
    local ok, result = pcall(api_fn, ...)
    if ok then return result end
    return nil
end

return M
```

**Acceptance Criteria:**
- Document every pcall location with: file, line, function name, call frequency, and whether it can be cached
- Identify hot-path APIs that can be cached at module load
- Identify APIs that still need pcall (frame probes, addon queries)

**Verification:**
```powershell
grep -n "pcall" EaxAutoQuester/*.lua | wc -l  # baseline count
```

**Delegation Recommendation:**
- Category: `deep` — requires careful analysis of which APIs are safe to cache
- Skills: `debugging-and-error-recovery` — understand API failure modes
